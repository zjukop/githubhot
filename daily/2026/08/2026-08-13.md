### 3. [firecrawl/anydoc](https://github.com/firecrawl/anydoc)

#### 一句话定位

Anydoc 是一个以 Rust 实现的本地文档转换库，把 Word、PowerPoint、Excel、OpenDocument、RTF、EPUB、CSV 和文本型 PDF 转成干净的 GitHub-Flavored Markdown，并提供 Node.js 与 Python 绑定。它强调无需外部服务、基于文件内容识别格式和低延迟转换。

#### 适合谁、用在什么场景

- 为 RAG、知识库或文档检索流程准备 Markdown 数据的 AI 应用开发者。
- 需要批量转换办公文档但不希望文件上传第三方服务的团队。
- 希望在 Node.js、Python 或 Rust 项目中嵌入文档解析能力的工程师。

#### 核心能力与价值

- 覆盖多种办公和电子书格式，并把结果统一为适合代码与 AI 流程处理的 Markdown。
- 根据文件字节而非扩展名判断格式，能减少文件命名错误导致的转换失败。
- 纯 Rust、本地运行且不依赖 ML 服务，并通过 Node.js 线程池和 Python 释放 GIL 避免阻塞宿主应用。
- 保留嵌入资源信息，并内置文本型 PDF 转换能力。

#### 技术实现观察

- Rust 核心配合 Node.js/Python Binding，使性能敏感逻辑集中实现，同时覆盖常见应用生态。
- 内容识别和多格式解析意味着项目的主要工程难点在文件格式边界、异常文档和一致输出，而不是模型效果。
- 官方说明 PDF 转换不包含 OCR 服务，因此扫描型 PDF 的能力边界需要特别区分。

#### 为什么值得关注

- 文档转 Markdown 是 RAG、Agent 和知识库的基础环节，本地高性能方案能降低隐私风险和外部 API 成本。
- 较短时间内积累大量关注并连续发布版本，说明开发者对统一文档解析组件存在明显兴趣。

#### 成熟度判断

#### 局限与采用风险

- 复杂版式、公式、图表和扫描型 PDF 的保真度需要用真实文档集测试。
- 不同语言 Binding 的版本同步和跨平台二进制分发需要持续观察。
